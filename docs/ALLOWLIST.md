# 크롤링 화이트리스트 (crawl allowlist)

봇의 코퍼스에 반영할 목적으로 웹에서 자료를 수집해도 되는 도메인 목록.
**원칙: "카테고리"(공공기관 전체 등)가 아니라 아래에 나열된 도메인만 허용한다.**
목록 확장은 반드시 사람이 검토해서 이 파일을 고치는 방식으로만 한다.

## Tier 1 — SKKU 공식 (학사 규정의 최종 권위, 최우선)

- `skku.edu` 및 모든 서브도메인 (www/en/ghi/oia 등)
- 성균관대 공식 공지·안내 페이지 (위 도메인 하부)

비고: 학사 규정·일정·시설 안내는 Tier 1과 충돌하면 Tier 1이 이긴다.

## Tier 2 — 대한민국 공공기관·공식기관 (서울생활 코퍼스 주제와 직결)

교환학생 실무 정보(출입국·보험·교통·철도)의 공식 출처. 정부 기관은 출처
신뢰도가 높고 페이지가 안정적이므로 허용한다. 단 공기업·위탁사업자는
`.go.kr`이 아닌 경우가 많아 개별 도메인으로 명시했다.

- `hikorea.go.kr` — 하이코리아 (외국인등록·체류, ARC)
- `gov.kr` — 정부24
- `seoul.go.kr` — 서울시 (따릉이, 생활 정보)
- `nhis.or.kr` — 국민건강보험공단 (외국인 건강보험)
- `letskorail.com` / `korail.com` — 철도 공사 (KTX 예매)
- `t-moneycorp.com` — 티머니 (교통카드)
- `1397.go.kr` 등 이민(immigration) 관련 정부 페이지
- `moj.go.kr` / `mofa.go.kr` — 법무부·외교부 (비자·체류)

## Tier 3 — 조건부 (정보는 유용하나 상업·변동성 큼)

코퍼스 반영은 원칙적으로 금지하고, "확인 필요 — 공식 출처로 재검증" 용도로만
참고한다. 은행(우리은행 등), 통신사, 사설 어플 안내 포함. 필요시 Tier 1/2의
공식 페이지에서 같은 사실을 확인해 그쪽 출처로만 반영한다.

## 금지 (크롤 자체 불가)

- 개인 블로그·커뮤니티·카페·위키 (사실 검증 불가, 낡은 정보 다수)
- SNS, 댓글/UGC가 본문인 페이지

## 공통 규칙 (모든 티어에 적용)

1. 크롤한 내용은 **사람이 git diff로 승인하기 전까지 코퍼스에 머지하지 않는다.**
   이게 프롬프트 인젝션 방어의 최종 게이트다.
2. 크롤 결과는 그대로 붙여넣지 않고 코퍼스 문서 형식(요약·이중언어 앵커·출처
   frontmatter)으로 재구성한다. `retrieved:` 날짜와 원본 URL을 반드시 남긴다.
3. 요금·일정·모집 같은 변동성 정보는 문서에 "기준 시점 + 확인 경로(부서/전화/공지)"를
   함께 적는다 (운동시설 문서의 매월 공지 안내가 모범 사례).
4. 크롤 도중 이 목록 밖의 도메인으로 리다이렉트되면 그 페이지는 버린다.

## 도구: Firecrawl CLI (2층 보강 세션용)

심판 리포트(logs/review_*.md)에서 gap 주제가 확인됐을 때 쓰는 크롤 도구.
인증/크레딧 상태는 `firecrawl --status` 로 확인.

- 페이지 1장: `firecrawl scrape -f markdown --only-main-content "<URL>"`
  — 본문만 마크다운으로. SKKU 공지는 표 셀 안에 `<br>` 이어붙임으로 나오므로
    반드시 재구성해서 코퍼스에 넣는다(공통 규칙 2).
- 사이트 구조 탐색: `firecrawl map "<도메인>"` — 어느 페이지를 긁을지 고를 때.
- 공식 페이지 탐색: `firecrawl search "<검색어" site:skku.edu"` 식으로 범위 제한.
- 정기 갱신 대상(학사일정·모집 공지)은 `firecrawl monitor` 로 변경 감지를 고려할 수 있다.

구분: **아침 심판(1층)은 WebFetch만 쓴다**(비용 없음). Firecrawl 크레딧은
2층 보강 세션에서 실제로 코퍼스에 넣을 자료를 긁을 때만 쓴다. `.firecrawl/`
캐시는 gitignore 처리돼 있어 실수로 커밋되지 않는다.
